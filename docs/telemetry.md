# Telemetry mode

The command `bun run solve` records a search tree and writes profile files to `data/`. It needs no browser.

Telemetry is on by default. The flag `--showcase` turns it off for a plain, fast solve.

## Usage

```
bun run solve <map> [--thread N] [--pops N] [--seconds S]   # telemetry (default)
bun run solve <map> --summary                                    # also print a static summary
bun run solve <map> --showcase                               # no tracing, no export
```

| Argument | Meaning |
| --- | --- |
| `<map>` | A map name from `maps/` (with or without `.txt`), or a path to a map file |
| `--thread N` | The solver thread configuration to trace, from 0 to 3. See `solvers/portfolio/include/flags.h`. Default `0` |
| `--set key=value` | Override one field of the traced thread configuration. The flag can repeat. Numeric keys: `h_weight`, `switch_penalty`, `g_weight`, `walk_weight`, `noise_weight`, `switch_penalty_floor`, `max_g_rate`, `g_rate_step`. Also `stagnation=none\|full\|pocket\|bounded` |
| `--pops N` | Stop after N expansions. Default: no limit |
| `--seconds S` | Stop after S seconds. Default: no limit |
| `--summary` | After the run, print a static summary. It shows best-heuristic and depth sparklines, states per depth, where pushes went, and the slowest phases. The run still exports files |
| `--showcase` | Run plain `sokosolve`. It prints the solution and the time. It exports nothing |

Examples:

```
bun run solve 1-5_Sokoban-Original-and-Extra-5
bun run solve 1-5_Sokoban-Original-and-Extra-5 --thread 2 --seconds 30
bun run solve 100-1_Sokoban-TBox-1 --pops 50000
bun run solve 1-1_Sokoban-Original-and-Extra-1 --showcase
```

The first run builds `sokotrace` through `make` when the binary is missing. A `--showcase` run builds `sokosolve` instead.

## Output layout

Each run writes into its own folder under `data/`. The folder name is `<date>_<time>_<mapname>`.

```
data/
  2026-10-31_10-12-01_1-5_Sokoban-Original-and-Extra-5/
    1-5_Sokoban-Original-and-Extra-5-depth-profile-10-12-01.csv
    1-5_Sokoban-Original-and-Extra-5-search-progress-10-12-01.csv
    1-5_Sokoban-Original-and-Extra-5-summary-10-12-01.json
```

- The folder name holds the date (`YYYY-MM-DD`), the local time (`HH-mm-ss`), and the map name without `.txt`.
- File names match the export buttons of the web UI. Each name also holds the local time of the run.
- The terminal UI writes the same files when you press `E` in the explorer view.
- Git ignores `data/`.

## File contents

### Depth profile CSV

The file `*-depth-profile-*.csv` holds one row per search tree depth. Depth counts the pushes from the start.

| Column | Meaning |
| --- | --- |
| `depth` | Depth in the search tree |
| `states` | States generated at this depth |
| `expanded` / `queued` / `dropped` / `solution` | What became of those states |
| `children_of_expanded` | Total children generated by the expanded states |
| `avg_branching` | `children_of_expanded / expanded` |
| `avg_heuristic` / `min_heuristic` | Heuristic estimate (pushes to goal) across the depth |

### Search progress CSV

The file `*-search-progress-*.csv` replays the run in expansion order. It holds about 400 points.

| Column | Meaning |
| --- | --- |
| `expansion` | Expansion number |
| `best_heuristic` | Lowest heuristic reached so far |
| `cumulative_microseconds` | Solver time spent so far |
| `depth` | Depth of the state expanded at that point |

### Summary JSON

The file `*-summary-*.json` holds the run totals from the tracer:

- `threadId`, `width`, `height`
- `expansionCount`, `nodeCount`
- `isSolved`
- `stopReason` is `""` (finished), `expansions`, `time`, `size`, `stopped`, or `pool`. The value `pool` means the 10M state pool filled before the solver found a solution.
- `totalNanoseconds`
- `phaseNanoseconds` holds the time per solver phase.
- `reasonTotals` holds the rejected pushes per prune reason.
- `switchPenalty`

## Notes

- **Choosing threads.** The command `SOKO_THREADS=4 bin/sokosolve < map.txt` runs only the listed thread configurations. Separate them with commas. Without the variable, the solver runs the first N enabled configurations. N is the core count.
- **One thread per run.** Telemetry traces one thread configuration, not the race of all threads. The data describes that thread, not the overall winner. Tracing adds overhead, so use `--showcase` to measure time.
- **Size limit.** The tracer stops at 10,000,000 nodes (`stopReason: "size"`). Use `--pops` or `--seconds` to bound very hard maps.
- **Shared code.** The CSV logic lives in `core/src/domain/tree-profile.ts`. The web UI, the terminal UI, and the CLI all use it, so all three produce the same columns.
