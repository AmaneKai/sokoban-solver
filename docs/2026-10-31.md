## 2. Detailed audit trail

### Audit entry #001: Baseline diagnosis of level `1-9`

* **Source artifacts:** `1-9_...-summary.json`, `...-search-progress.csv`, `...-depth-profile.csv`
* **Performance baseline:**
  * **Expansions:** 7,919,899 nodes
  * **Search time:** 23.132 seconds
  * **Major bottlenecks:**
    * `kHeuristic`: 4.82 s (20.8%)
    * `kPlayerFlood`: 4.24 s (18.3%)
    * Stagnation stall: 7,880,000 expansions spent at `h = 57`

#### Root cause analysis
1. **False priority reset bug:** `Solver::Run()` reset `best_priority_seen` to `UINT64_MAX` after each reheap. The search explored deep branches that fell from high heuristic values (for example `235` down to `58`). The test `popped_priority < best_priority_seen` kept firing. It reset `stagnant_pops_ = 0` and hid real stagnation.
2. **`DestNotCutVertex` player-square invalidation:** `DestNotCutVertex(dest)` checked player reachability across the ring neighbors with `reach_ == reach_seq_`. The cell `orig_b_pos` had held a box, so it lacked the current reach marker. The `fast_path` normalization then failed near walls. This forced expensive full BFS flood fills (4.24 s in total).
3. **Redundant wall walking in heuristics:** `LinearConflictPenalty` walked cell by cell (`map_[c] == '#'`) across static board boundaries. It did this millions of times per run.
4. **No-op Hall check:** `HasFeasibleGoalAssignment` exited early whenever all boxes held assigned goals (`cached_goal_of[b] != 0xFF`). The check was a 0.13 s no-op with 0 prunes.

#### Applied fixes
* The team decoupled the `stagnant_pops_` increments from priority comparisons. The counter now resets only on a true heuristic improvement (`h < best_h_seen_`).
* The team set `reach_[orig_b_pos] = reach_seq_` for the duration of each `DestNotCutVertex` check. This restored the `fast_path` player normalization.
* The team precomputed the static contiguous row and column segments (`row_seg_`, `col_seg_`) in `board.cpp`. A wall check became an $O(1)$ ID comparison.
* The team deferred the `goal_of` copy in `ExpandNode` until after the duplicate hash filter.

### Audit entry #002: Iteration 1 evaluation and reheap stagnation flaw

* **Source artifacts:** Intermediate `application/json` and `text/csv` files
* **Performance measured:**
  * **Expansions:** 3,326,687 nodes (58% reduction)
  * **Search time:** 8.486 seconds (2.7× faster)
  * **Hotspot drops:**
    * `kPlayerFlood`: 4.24 s to 1.14 s
    * `kHeuristic`: 4.82 s to 2.07 s

#### Root cause analysis
* **Priority escalation discrepancy:** The solver needed 132 sequential reheaps to surface the winning `depth = 23` node.
* Older nodes in `pq_` collected several reheap penalties ($K \times g \times 1.5\text{M}$). New states from recent dives entered with zero reheap penalty.
* The new dive branches kept priorities well below the valid shallow recovery nodes. Dozens of consecutive reheaps had to close the gap.

#### Applied fixes
* The team tracked `pool_ptr_` across reheaps with `last_reheap_pool_ptr`.
* The team applied tiered penalty weights:
  * New dive nodes (`idx >= last_reheap_pool_ptr`) received a heavy penalty from the cumulative rate.
  * Existing frontier nodes (`idx < last_reheap_pool_ptr`) received one delta rate.

### Audit entry #003: Iteration 2 results on level `1-9`

* **Source artifacts:** `1-9_...-summary.json` (Thread 0), `...-search-progress.csv`, `...-depth-profile.csv`
* **Performance measured:**
  * **Expansions:** 2,353,006 nodes (70.3% reduction from baseline)
  * **Search time:** 5.902 seconds (3.9× faster than baseline)

#### Observations
* The solver reached the key recovery band at `depth = 38..48` within about 250K expansions.
* Too many reheaps then raised the `g` penalties. The solver expanded irrelevant shallow states (`depth = 12..28`) for 1.82M expansions. It then returned to `depth = 46`.
* After the solver popped `depth = 46`, it finished the solution in 206 expansions (0.86 ms).

### Audit entry #004: Diagnosis of level `1-11` and the switching conflict

* **Source artifacts:** `1-11_...-summary.json`, `...-search-progress.csv`, `...-depth-profile.csv`
* **Outcome:** Failed. The search exhausted the 10,000,000 node pool without a solution.

#### Root cause analysis
1. **Heuristic penalty domination:**
   * Congested multi-room levels like `1-11` need frequent box switching (about 1 switch per 2 pushes).
   * At `switch_penalty = 2,000,000` (`2.0× h_weight`), each switch adds $+2\text{M}$ to the priority. A push toward the goal removes only $-1\text{M}$.
   * Deep states with a better heuristic got worse priorities than hundreds of thousands of weak shallow nodes. One deep state had `depth = 86, h = 183`. The shallow nodes had `depth = 30, h = 255`.
2. **Runaway breadth-first expansion:**
   * The search stagnated at high heuristic values (`h = 244`). Repeated reheaps raised `cumulative_g_rate` to $122.7\text{M} \times g$.
   * The search flattened into unguided breadth-first search. It filled memory across shallow depths (305,000 nodes per depth level).

### Audit entry #005: Iteration 3 and 4 regression analysis

* **Source artifacts:** Intermediate `application/json` and `text/csv` files, and build error logs
* **Failure modes identified:**
  1. **Compilation inconsistency:** The team restructured `SokoState` and replaced `push_from` with `h`. A partial file patch caused a temporary compiler error.
  2. **Switch penalty zeroing trap:** Setting `active_switch_penalty_` to `0` made the engine thrash across all candidate boxes. Progress stopped at `h = 190`.
  3. **High-cost freeze BFS overhead:** The team tried a complete reverse-pull reachability check inside `HasDeadEmptyGoal`. The check added an expensive BFS. It raised `phaseNanoseconds[14]` from 0.37 s to 11.13 s (a 30× slowdown).
  4. **Premature penalty wipes:** The code reset `cumulative_g_rate = 0` on every 8th reheap. Map `1-9` then abandoned its promising deep recovery frontiers. Node counts rose back to 8.85M.

---

### Audit entry #006: Final architecture stabilization

* **Target goal:** Keep `1-9` under 6 seconds. Build a sound recovery model for congested maps like `1-11`.

#### Refactored mechanics
1. **Reverted the expensive deadlock BFS:**
   * The team restored the $O(1)$ static table checks for `HasDeadEmptyGoal`.
   * This removed the 11.13 s runtime overhead in `kPushChecks`.
2. **Normalized the state layout:**
   * The team kept `u16 h` in `SokoState` and removed the redundant `push_from`. The solver derives `push_from` as `last_dest - (macro_steps + 1) * dirs_[push_dir]`.
   * The layout kept its exact 24-byte alignment with no memory growth.
3. **Calibrated adaptive reheaping:**
   * The team kept `switch_penalty = 2.0M` and `1.5M` for the initial aggressive search.
   * The team lowered `kRecoveryStagnationLimit` from 8,000 to **4,000** pops in recovery mode.
   * When `best_h_seen_` improves during recovery, the solver reheaps the states cleanly. This keeps the new low-`h` frontier without runaway penalties.
   * The team set a floor of **500,000** (`0.5× h_weight`) for `active_switch_penalty_`. Congested phases can still switch boxes. Non-productive box thrashing stops.

## 3. Key findings and rules

1. **Heuristic and switch penalty parity:**
   * A switch penalty above `1.0× h_weight` makes searches on congested puzzles stagnate before they reach deeper solution paths.
   * A switch penalty of `0` makes the search thrash across unrelated boxes.
   * The best ratio for congested maps is about `0.5× h_weight`.
2. **Frontier age in priority queue reheaping:**
   * A uniform `g` penalty across the whole queue punishes long-lived nodes too much.
   * The solver must tell new dive nodes (`idx >= last_reheap_pool_ptr`) from existing frontier states. This prevents runaway backtracking.
3. **Deadlock pruning complexity budget:**
   * Each deadlock filter that runs on every push candidate must finish in $O(1)$ time.
   * A check with a graph traversal inside `ExpandNode` costs more throughput than it saves in state space. The dynamic reverse-pull BFS is one example.
